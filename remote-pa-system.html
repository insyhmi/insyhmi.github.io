RGS Remote Public Announcement System

A software project by Idlan Syahmi Ishak

The RGS Remote Public Announcement (PA) System is a real-time audio broadcast and management system commissioned by Reigate Grammar School KL.

Overview

The RGS Remote PA System is a full-stack, client-server application designed to facilitate audio broadcasting throughout the school using the local network.

The system runs on a dedicated host machine and outputs audio directly through connected physical PA speakers, allowing authorized users to control the school's announcement system remotely through a web browser.

This software is proprietary to RGSKL, with development and maintenance responsibilities managed by me in accordance with the terms of our agreement.

1. Project Background

1.1 Limited Accessibility to the PA System

  • The school previously relied on a physical microphone located inside the PA room to make live announcements.
  • Staff members had to physically walk to the PA room whenever they needed to make an announcement.
  • This inconvenience was especially prominent for staff located far from the room.
  • It created inefficiencies during routine and urgent broadcasts alike.

1.2 Lack of Automated Scheduling

  • Manual broadcasting meant that every announcement had to be delivered in person, whether it was a one-time message or a recurring event.
  • Staff requested the ability to automate announcements and schedule them in advance for specific school events.

1.3 Demand for Text-to-Speech (TTS) Engine

  • Staff frequently needed to make announcements using standard or recurring phrases and templates.
  • Repeatedly recording or manually speaking these announcements was inefficient.
  • Staff requested an integrated Text-to-Speech system to automatically generate clear announcements from predefined text.

Overall, the existing PA system depended heavily on manual operation, provided limited accessibility, and lacked automation for scheduled and repetitive announcements. These limitations formulated a demand for a centralized system which allows authorized staff to remotely manage, automate, and broadcast announcements through the school's existing PA infrastructure.

2. Objectives

2.1 Improve Accessibility to the PA System

  • Develop a web-based system that allows authorized staff to remotely control and broadcast announcements through the school's PA system.
  • Eliminate the physical barrier of needing to enter the PA room to make announcements.

2.2 Automate Announcement Scheduling

  • Implement a scheduling system that allows staff to configure one-time and recurring announcements in advance.
  • Reduce the need for manual intervention during daily routine broadcasts.

2.3 Implement Text-to-Speech (TTS) Announcements

  • Integrate a local Text-to-Speech (TTS) engine that generates spoken announcements directly from predefined text.
  • Streamline standard and frequently repeated announcements using pre-saved templates.

3. Primary Features

The primary features of this system include:

  • User authentications and role-based access control (RBAC)

Users log in with a username and password, and each account is assigned a role (admin/regular user) stored in the session. Role determines which settings and actions a user can access — for example, only admins can modify system-level settings or manage other users' schedules.

  • Manage and play media files through a media queue

Uploaded audio files (WAV/MP3) are tracked in a database with metadata such as filename, uploader, and upload time. Files can be organized into a queue and played back sequentially through the server's audio output, with configurable gaps between tracks.

  • Live microphone audio from client in real time

A client's microphone input is captured in the browser, streamed to the server over a WebSocket connection, and played out through the server's audio device in real time — enabling live announcements to be broadcast as they're spoken.

  • Synthesize speech announcements using a local neural TTS engine

Text input is converted to spoken audio using Kokoro TTS by hexgrad, an open-weight text-to-speech engine with 82 million parameters loaded locally, with multiple voice options and an adjustable speed value. Generated announcements can optionally be previewed locally before being broadcast live.

  • Schedule announcements

Media queues or announcements can be scheduled to play automatically at a specific time (one-time) or on a recurring basis (via cron expressions), without requiring manual playback.

  • User management and system settings via an admin control panel

Administrators can create and manage user accounts, assign roles, and configure system-wide settings (audio parameters, TTS defaults, scheduling behavior, storage limits, and security settings) through a dedicated settings interface, with changes taking effect without requiring a server restart.

  • ISO 8601 Logging format

Server activity (including errors, warnings, and informational messages) is timestamped and written to daily log files, with each entry recorded in an ISO 8601-style format for consistent, unambiguous chronological tracking.

4. User Guide

This section describes the typical workflow for using the system from the client side, including the main operations available to users.

4.1 Signing In

  • At the login screen, enter the username and password assigned to the user.
  • Press Sign in to access the system.

4.2 Navigation

  • After signing in, the user will be greeted by the Media Player page by default.
  • To navigate to other pages, press the menu button ☰.
  • Select the page that the user wishes to access.
  • To access the system settings, press the Settings button ⚙.
  • After completing the desired tasks, press Log out to end the current session.
  • There is a PA Control section at each of the control pages.

4.3 Media Player

  • The Media Player page allows users to arrange and broadcast multiple audio files sequentially through the PA system.
  • To add audio files to the queue, press Add Media under the PA Player Controls.

  • Select the desired audio files and press Add Selected.

  • To rearrange the queue, click and drag an audio file to the desired position.
  • Press the Play button ▶ to begin broadcasting. The audio files will be played sequentially from the top of the queue to the bottom.
  • Press the Stop button ■ to stop broadcasting before the queue finishes.

  • To remove an audio file from the queue, hover over the desired item and press the Remove button.

4.4 Live Mic

  • The Live Mic page allows users to broadcast real-time voice announcements from their browser through the PA system.
  • The Prequeue is the media queue that will be broadcast before the microphone is connected, while the Postqueue is the media queue that will be broadcast after the microphone is disconnected.
  • To add audio files to either queue, press Add Media under the PA Player Controls and select the desired queue type.
  • Select the desired audio files and press Add Selected.
  • Press the Play button to start the broadcasting sequence and microphone connection.

  • Microphone permission must be granted by the browser before live microphone broadcasting can begin.
  • Adjust microphone gain to change the volume of the microphone.

4.5 Text to Speech

  • The Text to Speech page allows users to generate audio announcements from predefined text. It provides two modes: Live TTS and Generate TTS.
  • Live TTS generates and broadcasts the announcement immediately. If preview is enabled, the generated speech will first be played through the user's browser.
  • Generate TTS generates the speech and saves the resulting audio file on the server for future use.
  • To generate a speech announcement, enter the desired text into the text box, select a voice character, and press Play.

  • If preview is enabled, the generated speech will be played through the user's browser. The user can hence choose to start broadcasting it through the PA system if they are satisfied, or discard it.

4.6 Schedule

  • The Schedule page contains all scheduled announcements to be played in the future.
  • There are two modes for schedules. One Time creates an announcement at a specific day and time, while Recurring allows an announcement to be repeated until disabled.

  • Press New to create a new schedule .
  • Enter the details for the new schedule, including the name, type, and the media queue.

  • To modify a schedule, click on a schedule, and press Modify. Adjust the schedule accordingly.
  • After modifying, press Update schedule. The schedule will now be broadcasted according to the new parameters.
  • To toggle a schedule active or disabling it, press Toggle. A one-time schedule will automatically updated to inactive once it runs.
  • To delete a schdedule, click on a schedule, and press Delete.

4.7 Audio Manager

  • The Audio Manager page allow users to Audio Manager and upload new files into the server. It allows user to view all files and its details, modify its name as well as removing it from the server.

  • To upload an audio file, click on Upload section, select a file and click upload Media Files.

  • To view an audio's details, choose an audio file and click View.
  • To modify the audio's display name, click Modify. Enter the details and click Save.
  • To download the audio into the device, click Download.
  • To remove the audio from the server, click Delete.
